# Vidya Vedika
## AI Language Learning & Mock Interview Platform

**Document Type:** Technical & Functional Project Documentation  
**Platform:** Vidya Vedika  
**Architecture:** React + Spring Boot Microservices  
**Primary Database:** MySQL  
**AI Architecture:** Pluggable AI Provider Model  
**Target:** Production-oriented Educational SaaS Platform

---

# 1. Executive Summary

Vidya Vedika is a modern educational SaaS platform designed to combine:

- Language learning
- Daily language practice
- Vocabulary development
- Grammar and sentence correction
- AI-powered conversation practice
- Mock interview preparation
- Learning progress tracking
- Student analytics
- Administrative content management
- Optional financial support/contributions

The platform is intended to support learners from beginner through advanced levels while providing personalized practice and feedback.

The core product concept is:

> **Learn → Practice → Receive Feedback → Track Progress → Improve → Prepare for Real-World Communication**

The platform is designed as a responsive web application with a React frontend and Java 17+/Spring Boot microservices backend.

---

# 2. Product Vision

Vidya Vedika aims to provide a single platform where a learner can:

1. Create an account.
2. Select languages and learning goals.
3. Follow structured lessons.
4. Practice vocabulary and grammar.
5. Complete daily learning activities.
6. Practice conversations with AI.
7. Submit sentences for correction.

# 13. AI Provider Architecture

The AI layer is deliberately abstracted.

text
                 AIProvider
                     │
          ┌──────────┼──────────┐
          │          │          │
          ▼          ▼          ▼
       Ollama      Gemini    Other Provider


Example interface:

java
public interface AIProvider {

    AIResponse generate(AIRequest request);

}


Possible implementations:

text
OllamaAIProvider
GeminiAIProvider
OpenAICompatibleProvider
FallbackAIProvider


This means the business logic does not need to know which AI provider is being used.

The specification specifically requires that AI providers be swappable and that API keys never be hard-coded.

# 68. Conclusion

Vidya Vedika is intended to be more than a language-learning website. Its architecture combines structured education, personalized practice, AI-assisted feedback, interview preparation, progress analytics, and administrative content management into one platform.

The core learner experience is:

**Discover → Learn → Practice → Receive AI Feedback → Track Progress → Practice Interviews → Improve**

The architecture is deliberately modular so that additional languages, lessons, AI providers, interview categories, voice capabilities, and scalability features can be introduced without redesigning the entire platform.

The supplied specification identifies the final deliverables as a complete React frontend, Spring Boot microservices, MySQL design, REST APIs, JWT security, admin/user portals, AI abstraction, Ollama support, Docker, GitHub Actions, environment configuration, seed data, tests, README, deployment guidance, architecture documentation, and API documentation.


| Area | System-design component |
|---|---|
| Frontend | React + TypeScript + Vite |
| Entry point | API Gateway |
| Authentication | Auth Service + JWT |
| Authorization | Roles/RBAC |
| Users | User Service |
| Languages | Language Service |
| Learning | Learning Service |
| AI conversations | AI Practice Service |
| AI provider | Provider abstraction + Ollama |
| Sentence correction | AI Practice functionality |
| Mock interviews | Mock Interview Service |
| Contributions | Payment Service |
| Notifications | Notification Service |
| Administration | Admin Service |
| Database | MySQL |
| Deployment | Docker |
| CI/CD | GitHub Actions |
| Service discovery | Eureka where appropriate |
| Security | Spring Security + JWT + BCrypt |
| Validation | Bean Validation |
| API communication | REST/OpenFeign where appropriate |

-------------

| Pattern | Where to use it | Purpose |
|---|---|---|
| **Strategy Pattern** | AI Provider | Switch between Ollama, Gemini, OpenAI, etc. |
| **Factory Pattern** | AI Provider creation | Create the appropriate AI provider |
| **Adapter Pattern** | External AI/payment services | Make different external APIs look consistent |
| **Repository Pattern** | Every service | Separate persistence from business logic |
| **Service Layer Pattern** | Spring Boot services | Keep business logic out of controllers |
| **DTO Pattern** | REST APIs | Don't expose JPA entities directly |
| **Builder Pattern** | Complex objects / API responses | Clean object construction |
| **Facade Pattern** | Complex workflows | Provide a simple interface to multiple components |
| **Observer / Event-Driven Pattern** | Notifications | React to events such as registration/interview completion |
| **Circuit Breaker** | AI/external services | Prevent cascading failures |
| **Retry Pattern** | External API calls | Retry transient failures |
| **Saga Pattern** | Multi-service workflows | Manage distributed transactions |
| **Dependency Injection** | Spring Boot | Loose coupling and testability |
| **MVC Pattern** | REST services | Controller → Service → Repository separation |
